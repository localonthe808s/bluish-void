## 7. Fix on this branch

`trail_row()` reads `today.own5_row` for `obs.own5_last` and `obs.own5_at`, but nothing ever wrote that key. Both
fields were null on every published row (0 of 637 own5 rows on 10-03 and 10-04 had them), so the trail could not show
that the 5-minute feed had gone stale. The fix is one line in the today dict (`_kalshi/kalshi_daily.py:5005`):
`'own5_row': own5_row(cfg, today)`. It reuses the worker summary that the same bake already fetched, so it adds no
fetch.

Replay (`trail_row` on aus_high 2026-10-04 with the live worker summary):
- Before: `{'own5': 77.0, 'own5_last': None, 'own5_at': None}`
- After: `{'own5': 77.0, 'own5_last': 75.2, 'own5_at': '23:45'}`
- NY has no own feed: `own5_row` returns None, so its fields stay null as before.

py_compile passes. No learned value, guardrail or court was touched. The freeze itself lives in the worker, which this
branch does not change.
