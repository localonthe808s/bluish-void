## 7. Fix on this branch

`forecast_runs()` takes history from the historical-forecast archive, which **ends yesterday**. It takes today and
tomorrow from the live API. When the live call fails, the log says "today falls back to archive", but the archive has no
today. `fcm` is not empty, so the existing `if not fcm: return 0` guard does not fire. `point_forecast()` then returns
None, `pred = max(obs_far, None)` becomes the morning running max, and the day is not "binding", so the bake still
publishes the full ladder around it. The result is a 7 AM reading quoted as the high at p=1.0. If the outage hit a
12:0x bake, the noon lock (rebuilt from the same `fcm`) would be recorded that way.

Change (`_kalshi/kalshi_daily.py`, after the `if not fcm` check): if no model holds any hour for today, print
`no forecast run for today (live run unavailable); not writing` and return 0. This is the same exit as "no forecast
models available". The previous bake stays on the sheet, and the next one (5 minutes later) recovers. This matches
what happened on its own at 07:41.

Replay: `forecast_runs()` called with the archive answering through 10-09 and the live URL raising HTTP 500:
- Before: `fcm` holds 6 models with days 10-07..10-09 only; `point_forecast(...)` = None; pred = max(58.606, None) =
  **58.606**. This matches trail row 07:36 (pred 58.61, p 1.0).
- After: the guard is true, the bake returns 0 and nothing is written. The sheet keeps the 07:31 bake (68.24, 68-69 at 0.67).

py_compile passes. The lows (`kalshi_lows.py:480`) and price_study call the same `forecast_runs`. I did not change
them: the 8 AM low is mostly observed by then, and price_study is offline.
