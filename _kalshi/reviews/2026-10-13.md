## 7. Fix on this branch

`_kalshi/kalshi_daily.py` `_run_market`, right after the "no forecast models available" check.

**Cause.** `forecast_runs` reads the archive through yesterday, then today from the live API. When the live call
fails it prints "today falls back to archive", but the archive has no rows for today. `fcm` is non-empty, so the
existing guard passes. Then `point_forecast(...)` returns None, `pred = max(obs_far, None)` is the running maximum,
and the spread stays at the morning's (binding is false because `fadj` is None). The result is a ladder centered on
the 10 AM reading.

**Before (replay with the live call failing, archive ending 10-11):** `fcm non-empty: True, any run has today:
False, point_forecast: None, pred 60.796`. The trail row reads 10:26 pred 60.8, sd 0.964, "68 or below" p 1.0.

**After:** the new check `if not any(v.get(tkey) for v in fcm.values())` returns 0 with "no run carries today's
hours; keeping the last bake". The previous bake's file stays up, and the next 5-minute bake (10:31 that day) carries
on. A noon lock is taken at the first bake at or after 12:00 (`now.hour >= LOCK_HOUR`), so one skipped bake only
delays it by 5 minutes.

The fix touches no learned value and no guardrail. Locks already written are not rewritten.
