## 7. The fix: a missing live run no longer bakes the running max as the forecast (finding A)

**Cause.** `forecast_runs` reads the archive only up to yesterday (`end_date = today - 1`) and takes today from the
live API. When that live call fails it prints "today falls back to archive", but nothing for today is there. `fcm` is
non-empty, so the existing `if not fcm` guard passes. `point_forecast` then returns None, and `pred = max(obs_far)` is
the running max. `binding_now` stays false, which correctly keeps an open-day spread, but it is centred on the
morning's reading.

**Evidence (3 weeks of trail, 4907 bakes, 10 with `models` null):**

| day | time | pred | p | pick | final |
|---|---|---|---|---|---|
| 10-10 | 07:36 | 58.61 | 1.0 | 65 or below | other |
| 10-12 | 10:26 | 60.80 | 1.0 | 68 or below | other |
| 10-15 | 14:05 | 62.76 | 0.714 | 63 or below | other |
| 10-17 | 08:00, 08:30 | 58.64 | 0.999 | 61 or below | 62-63 |
| 10-20 | 09:30 | 58.70 | 1.0 | 64 or below | 67-68 |

The other 5 were evening bakes, where the floor already bound. Had any of these been the first bake at or after
12:00, the lock would have been written at p 1.0 and never rewritten.

**Change** (`_kalshi/kalshi_daily.py`, after `if not fcm`): if no model has a row for today, print it and return 0
without writing. This is the same treatment the bake already gives "no forecast models available", so the last good
bake stays on the sheet and the next 5-minute bake (or the 12:05 one, for the lock) takes over. No learned value,
threshold or guardrail is touched.

**Before/after (offline replay, live API forced to fail, archive stubbed from the URL's own dates):**

```
before (forecast_runs + point_forecast, unchanged code):

after (run_market on the branch):

  no model has today (2026-10-21); live run missing, not writing
  run_market -> 0
  kalshi_ny.json rewritten: False
```
