## 7. Fix on this branch

`_kalshi/insider_study.py` `fetch_r2()` fetched `cdn.bluishvoid.com/kalshi/trail/<key>_<d>.jsonl` with no query
string. It then cached the result **permanently** once the day was 2 or more days old (`cached('trail_...')`, kept by
actions/cache). So whatever copy the edge had pinned during that day became the study's input for good. The change
is one line: `?d=<today>`, the same key the 10-25 branch gave `index.html`. Only settled days are fetched, so a key
made from today's date is first fetched after day d ended.

Before and after, measured on the `obs.twc` rows that `fetch_r2` keeps:

|---|---|---|
| 10-23 | 64 rows to 06:00, twc {57.9} | 263 rows to 23:55, twc {57.9} |
| 10-24 | 82 rows to 07:00, twc {48.0}: **no rise** | 284 rows to 23:55, twc 48.0 -> 60.1 (7 values) |
| 10-25 | 69 rows to 06:00, twc {51.1}: **no rise** | 279 rows to 23:55, twc 51.1 -> 63.0 (6 values) |
