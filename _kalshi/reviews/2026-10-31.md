file's `max-age=120`. Because of that, the sheet's "yesterday" view shows 6 AM prices at the NOON, 2 PM, 6 PM and CLOSE
moments. This branch has a one-line fix for that view. Separately, the noon lock has come in too cold on 13 of the last
14 settled days.

Scope: New York only. Las Vegas and Austin were dropped on purpose on 10-06/07 (67021731, f7655a9a). Their six files
are frozen at 10-06 and still get mirrored. That is expected; this README still lists them under step 1.

Files for 10-20 to 10-23 come back whole. The ny_low files come back whole because the first request for each one
arrives after the day is over. The job log for run 41070248871 (10-30 14:16Z) says "appended 1 row(s) ->
ny_high_2026-10-30.jsonl (123 total)", so R2 has the rows and the edge copy is the stale one. The plain
`kalshi/live/kalshi_ny.json` is pinned the same way (age 518,561 s, last-modified 10-25 10:01Z). The live sheet is not
affected, because it adds `?v=<minute>` to every live read. The `_cdn-worker` routes do not cover `/kalshi/*`. That
points to a Cloudflare cache rule on cdn.bluishvoid.com that sets the edge TTL and overrides the origin. That rule is in
the dashboard, not this repo.

Effect on the sheet: the yesterday view (`index.html` cwkYesterday) fetches `ny_high_<yd>.jsonl` with no query string.
For each moment it picks the last row at or before that hour, so every moment falls back to the 06:00 row. Replayed for
10-30:

| moment | before: row / 69-70 yes ask / 68-or-below yes ask | after: row / 69-70 / 68-or-below |
|---|---|---|
| NOON | 06:00 / 39c / 58c | 12:05 / 71c / 1c |
| 2 PM | 06:00 / 39c / 58c | 14:05 / 98c / 1c |
| 6 PM | 06:00 / 39c / 58c | 18:05 / 100c / 1c |
| CLOSE | 06:00 / 39c / 58c | 23:55 / 100c / 1c |

Fix (index.html, one line): `fetch(... + key + '_' + yd + '.jsonl')` becomes `... + '.jsonl?v=' + yd`. This is the
same per-day key that `trail_study.py` already uses, which is why trail_study sees 283-290 bakes a day. It is safe
because `yd` is always a finished day. Parse check: all 39 inline scripts compile under Node `vm.Script`, before and
after. esprima would not build in this container, so Node did the parse instead.

Not fixed (the README allows one fix): `kalshi_daily.py` `trail_rows()` (execution score) and `insider_study.py:200`
fetch the same plain URL. insider_study's R2 twc reads for ny_high have covered only 00:00 to 06:00 ET since 10-24.
Either way, purging the cache and correcting the edge-TTL rule for `/kalshi/*` fixes the cause.

Other trail checks on 10-30: the high pick never flipped after noon. The low's "now" pick flipped 6 times after noon
between 50-51 and 52-53, with p about 0.47 and pred 51.5 sitting on the bracket edge. This is dithering, not a bug, and
the 08:00 lock was already fixed. For the low, `obs.six` going 57.02 to 55.04 at 19:56 is the right direction. No
`decided` or `locked` value contradicted the day.
