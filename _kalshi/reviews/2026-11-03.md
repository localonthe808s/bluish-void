**Finding (medium, fixed on this branch): a rejected push throws away the run's data.** In
`.github/workflows/kalshi-nyc.yml`, "Commit if changed" runs `git add` and `git commit` first. It then computes
`changed="$(git diff --name-only -- kalshi_*.json)"`. After the commit the working tree is clean, so `changed` is
always empty.

When the push is rejected, the step does `git reset --hard origin/main` and copies back nothing. `merge_head.py`
crashes on the missing temp file, which `|| true` hides. The step then prints "origin already has this data" and
exits 0, so the run's freshly baked files never land.

From the 11-02 log of run 41461796405:

```
[main 5cf841e] Kalshi daily highs: refresh market, probabilities and record
 2 files changed, 2 insertions(+), 2 deletions(-)
changed:
 ! [rejected]        main -> main (fetch first)
push rejected, replaying onto origin/main (attempt 1)
FileNotFoundError: [Errno 2] No such file or directory: '/tmp/tmp.Iea0AOIgel/kalshi_ny.json'
origin already has this data
```

That run only lost the report and dark files, because the bake itself had failed. But any run that overlaps another
push loses its whole bake the same way, including a normal bake on a slow day like this one. Overlapping runs did
happen (13:45Z ran to 13:58, 13:55Z ran to 14:07).

The fix is one line. It lists the files in the commit just made, not the now-clean working tree:

```diff
-          changed="$(git diff --name-only -- kalshi_*.json)"
+          changed="$(git diff --name-only HEAD~1 HEAD -- kalshi_*.json)"
```

`HEAD~1` exists even in the workflow's depth-1 checkout, because it is the checked-out commit itself.

Before/after: I ran the step's script verbatim in a sandbox. Setup: a bare remote, a `--depth 1` runner clone, and
another lane pushing `kalshi_ny.json` while the runner changes `kalshi_low_ny.json`.

| | `changed:` | outcome | remote kalshi_low_ny.json |
|---|---|---|---|
| before | (empty) | "origin already has this data", exit 0 | `{"v":"old"}` (this run's data lost) |
| after | kalshi_low_ny.json | replayed onto origin/main and pushed | `{"v":"THIS RUN low"}` |

In both cases the other lane's `kalshi_ny.json` survived. The workflow YAML still parses.
`kalshi-nyc-fast.yml` writes only `kalshi_ny.json` and does not have this bug.
