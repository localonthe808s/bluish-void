# Kalshi nightly review, 2026-11-16 (ET)

**Verdict:** The NY high sheet has been frozen since 15:20 ET on 11-15, and the NY low has shown no prediction since
15:25 ET. The cause is one dropped `['hourly']` in yesterday's archive-cache commit (`cbffb3a86`). Every run since has
been green. This branch carries the one-line fix and a replay. **Merge before 08:00 ET for the low lock and before
12:00 ET for the high lock**, or both locks for 11-16 will be missed.

## Findings

### 1. High: the bake silently stops writing the high, and the low lost its forecast (fixed on this branch)

Evidence:
- `kalshi_ny.json` `updated_utc` is 2026-11-15T20:21:38Z. It has had no commit since, while `kalshi_low_ny.json`,
  `kalshi_report.json` and `kalshi_dark.json` were committed every 5 minutes through 10:01Z.
- The CDN trail `ny_high_2026-11-15.jsonl` has 128 rows and ends at 15:20 ET. `ny_high_2026-11-16.jsonl` returns 404.
- The log of run 43844907156 (10:00Z) shows the high returning before any lock work:
  `not enough scored history for a bias (0 days)`, then `ny_high done in 10s`. There is no FAILED line and no
  ny_high trail row; only `ny_low_2026-11-16.jsonl` was appended.
- The `ny_low_2026-11-15` trail has `pred`, `pick` and `models` all null from 20:25Z (15:25 ET) through 23:57 ET, so
  the 20:00 ET low eve call never had a number. Today's low doc shows `today None 0%`.
- Timing: `cbffb3a86` was pushed at 20:22Z. The last good high bake was at 20:21Z.

Cause: `kalshi_daily.py:1945`. That commit changed `absorb(get_json(u, timeout=40)['hourly'])` to
`absorb(_archive_json(u))`. `_archive_json` returns the whole Open-Meteo response, so `absorb()` looks up
`temperature_2m_<model>` at the top level, finds nothing and keeps nothing. As a result:
- Every model's history is empty, so `rolling_bias` sees 0 days and `run_market` hits `return 0` (line 4438).
- `0` is not a dict, so `main()` folds no digest and the head file is not rewritten.
- Because nothing is raised, there is no `FAILED` line, and the worker watchdog stays `healthy: true`.
- The lows (`kalshi_lows.py:551`), `low_study.py:63` and `price_study.py:132` all go through the same
  `forecast_runs`.

Fix (this branch, `de6a744b6`): `absorb(_archive_json(u)['hourly'])`. The actions cache already holds whole responses,
so the cached copies stay valid.

Before/after, an offline replay of `forecast_runs` for ny_high (6 models, 40 past days). The archive call is stubbed
with an Open-Meteo-shaped response `{"hourly": {"time": [...], "temperature_2m_<model>": [...]}}`, and the live call
is made to fail:

| | days absorbed per model |
|---|---|
| main (`absorb(_archive_json(u))`) | 0, 0, 0, 0, 0, 0 |
| this branch (`['hourly']`) | 40, 40, 40, 40, 40, 40 |

The live bake was not run here (it would need the exchange and the runner's cache), so the first green run after the
merge is the real check. It should print a bias line and append a `ny_high` trail row.

Knock-on effects:
- **11-15 settlement.** The 11-15 high row has `actual` null because the bake stopped before settlement. It fills
  once the bake runs again.
- **Tonight's refit.** The nightly refit (cron 08:20Z, which has been starting around 15:00Z) would run
  `price_study.py` and `low_study.py` on empty forecasts if it starts before the merge.

### 2. Medium: the watchdog cannot see this kind of outage

The worker status page reads `healthy: true` and says the watchdog pages on "a green run whose log says a market
FAILED". This outage printed no FAILED line. `run_market`'s early `return 0` (no bias) is indistinguishable from
success in `main()`. I made no change, because the README allows one fix per branch.

A stale `updated_utc` on `kalshi_ny.json`, older than about 30 minutes, would have caught it at 20:51Z.
