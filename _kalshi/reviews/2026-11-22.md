## 7. The fix (on this branch)

**Cause.** In `_tune` (`_kalshi/tune.py:888`), when the incumbent replay fails, the function returns only
`{'active': ..., 'why': ...}`. That throws away the previous `n`. The bake's own `n >= 45` gate then switches off
every tuned value. That gate is a guardrail, so I did not loosen it. The fix is in tune.py: a failed replay now keeps
the last good entry whole, including its `n`, and only rewrites `why`.

```diff
-        return {'active': prev.get(key, {}).get('active'), 'why': 'incumbent replay failed'}
+        # keep the last good entry whole (its n too): without n the bake's n >= 45 gate drops every tuned
+        # value and runs on the typed defaults (no market or publish pull), as on 11-16 and 11-21
+        return dict(prev.get(key, {}), why='incumbent replay failed')
```

**Before and after.** I replayed `_tune` for ny_high, with `prev` = `tuned.json` as it was before 8e46404 and
`replay_with` made to fail. Then I applied the bake's gate to the result:

- before: `why='incumbent replay failed' n=None active.mkt_pull=0.65 active.pub_pull=0.75 -> bake applies tuned: False`
- after: `why='incumbent replay failed' n=67 active.mkt_pull=0.65 active.pub_pull=0.75 -> bake applies tuned: True`

This does not touch any learned value or any guardrail, and the file on main is unchanged. **Today still needs the
refit re-run by hand**, because main's `tuned.json` already lacks `n`.
